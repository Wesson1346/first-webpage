# TXT 阅读器 — 技术方案

> 版本：v0.1
> 日期：2026-09-01
> 对应产品文档：[产品设计文档.md](./产品设计文档.md)
> 技术决策：**Electron 桌面端 + Vite + TypeScript**（已确认）

## 1. 方案总览

将现有纯网页 Demo 演进为 Electron 桌面应用：渲染进程承载现有书架 + 阅读器 UI（迁移为 TypeScript），主进程提供原生「打开文件」对话框与窗口能力，数据仍存于渲染进程 IndexedDB。

选型要点：

| 项 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Electron | 用户选定；换取原生文件对话框、无浏览器存储限制、后续支持大文件与 EPUB 的空间 |
| 构建 | electron-vite | 官方生态事实标准，main / preload / renderer 三进程 TS 构建开箱即用 |
| 语言 | TypeScript | 全进程启用，存储层与分页等纯逻辑优先补全类型 |
| 存储 | IndexedDB（渲染进程） | 手写薄封装，不引第三方 ORM；桌面壳内无容量焦虑 |
| 编码识别 | `TextDecoder` | Chromium 原生支持 utf-8 / gbk，无需额外依赖 |
| 单测 | Vitest | 与 Vite 同一套配置；纯逻辑模块（分页、编码探测、进度计算）全部单测 |
| 打包 | electron-builder | MVP 仅出 Windows 本平台安装包 |

已知代价（接受）：安装包约 85MB、内存占用高于纯网页、开发需同时跑主/渲染两进程。

## 2. 进程架构

```
┌─────────────────────────────────────────────┐
│  Renderer（Chromium）                       │
│  ├─ 书架视图 / 阅读器视图（TS + DOM）        │
│  ├─ IndexedDB（books / progress / settings）│
│  └─ 经 preload 暴露的 window.api 调用 IPC   │
└──────────────┬──────────────────────────────┘
               │ contextBridge + ipcRenderer.invoke
┌──────────────┴──────────────────────────────┐
│  Main（Node）                               │
│  ├─ 窗口创建与生命周期                       │
│  ├─ dialog.showOpenDialog（选择 TXT）        │
│  └─ fs.readFile（读取选中文件原始字节）      │
└─────────────────────────────────────────────┘
```

原则：**主进程只做需要 Node 能力的事**（对话框、读文件字节），编码解析、分页、存储全部留在渲染进程，保证纯逻辑可单测。渲染进程不直接接触 Node API（`contextIsolation: true`，`nodeIntegration: false`）。

### IPC 接口（MVP 仅两条）

| Channel | 方向 | 入参 | 出参 |
|---|---|---|---|
| `book:pick` | renderer → main | 无 | `{ name, bytes: ArrayBuffer } \| null`（取消返回 null） |
| `book:read-by-path` | renderer → main | `path`（拖拽文件路径） | `{ name, bytes: ArrayBuffer } \| null` |

返回原始 `ArrayBuffer`，编码解码由渲染进程统一处理。

## 4. 核心模块设计

### 4.1 数据模型（IndexedDB）

数据库名 `txt-reader`，版本 1，三个 object store：

- **books**：`{ id, name, bytes: ArrayBuffer, encoding, importedAt }`，keyPath `id`（UUID）。整本书的字节存于此。
- **progress**：`{ bookId, pageIndex, percent, updatedAt }`，keyPath `bookId`。翻页时防抖写入（约 500ms），进入阅读器时读取定位。
- **settings**：`{ key, value }`，存字号档位与主题。与书无关，全局生效。

### 4.2 编码探测（`encoding.ts`）

```
decode(bytes: ArrayBuffer): { text: string; encoding: 'utf-8' | 'gbk' }
```

1. `new TextDecoder('utf-8', { fatal: true }).decode(bytes)`，成功即 UTF-8；
2. 抛错则回退 `new TextDecoder('gbk').decode(bytes)`；
3. 两者都失败时按 GBK 强解（容错，容忍少量乱码）。

注意：GBK 文件碰巧不含无效 UTF-8 序列的可能性极低，此策略对中文 TXT 实测可靠。

### 4.3 分页（`paginator.ts`）

沿用现有算法：按段落为单位装页，单段不拆分（超长段落独占一页，MVP 可接受），`charsPerPage` 由字号档位换算。签名改为 TS：

```ts
function paginate(paragraphs: string[], charsPerPage: number): string[][]
```

字号档位（3 档）与 `charsPerPage` 的映射表放在 `settings.ts`，换主题不换行宽，翻页结果不受影响。**翻页只在打开书或改变字号时重算**，翻页本身仅做索引移动，保证流畅。

### 4.4 导入流程

1. 点击「导入书籍」→ IPC `book:pick` 弹原生对话框（过滤器 `*.txt`）；
2. 或拖拽 TXT 到窗口 → `webContents` 的 `will-navigate` 拦截默认行为，取文件路径走 `book:read-by-path`；
3. 渲染进程拿到字节 → `decode()` → 按空行/换行切分段落 → 入库 books；
4. 重名文件允许重复导入（各自独立进度），MVP 不做去重。

### 4.5 阅读器与进度记忆

- 打开书：读 progress → 无记录则从第 0 页开始；
- 翻页：键盘 ←/→、点击正文左/右 35% 区域、底部上一页/下一页按钮，三者等价；
- 进度：页面索引变更即更新内存，500ms 防抖写 IndexedDB；同时更新书架百分比（`pageIndex / pages.length`）。

### 4.6 设置

- 字号：3 档（小/中/大），A- / A+ 循环切换，写 settings，重算分页并保持当前阅读位置的**段落锚点**（记录当前页首段落索引，重排后跳转到含该段落的页）；
- 主题：日/夜两套 CSS 变量，`data-theme` 属性切换，写 settings，启动时恢复。

## 5. 打包（electron-builder）

- `electron-builder.yml`：appId、productName「TXT 阅读器」、Windows nsis 目标；
- MVP 仅本平台（Windows）构建，macOS/Linux 配置预留但不验证；
- `userData` 目录留作后续导出/备份能力，MVP 不使用。

## 6. 测试策略（Vitest）

纯逻辑模块全部单测，不涉及 DOM/IPC 的部分占比 100%：

| 模块 | 用例 |
|---|---|
| `paginator.ts` | 迁移现有 `tests/paginator.test.js` 全部用例；新增：超长段落独占页、空输入 |
| `encoding.ts` | UTF-8 字节、GBK 字节、BOM 处理、非法字节回退 |
| `db.ts` | 封装层参数校验；IndexedDB 本身用 fake-indexeddb 在 Node 下跑集成用例 |
| progress 计算 | 百分比换算、边界（0 页 / 末页） |

现有 `node tests/paginator.test.js` 在迁移完成后删除，统一由 Vitest 执行。UI 与 IPC 走人工验收，对照产品文档第 8 节清单。

## 7. 实施步骤（每步独立 commit，测试随步交付）

1. **脚手架**：electron-vite 初始化、清理模板、electron-builder Windows 配置；`npm run dev` 可启动空窗口。
2. **存储层**：`db.ts` + `shared/types.ts` + 单测。
3. **导入链路**：IPC 两条通道、`encoding.ts` 及单测、拖拽支持。
4. **书架**：列表/进入/删除（带确认），数据源从 mock 切换到 IndexedDB。
5. **阅读器**：`paginator.ts` TS 迁移（含单测迁移）、翻页交互、进度记忆。
6. **设置**：字号与主题，重排时保持段落锚点。
7. **收尾**：删除旧网页 Demo 残留（`index.html`/`js/`/`css/` 根目录文件）、README 更新、全量测试通过、打包产物验证。

## 8. 风险与备忘

- **GBK 探测边界**：极短 GBK 文件（如只有 ASCII）会被判为 UTF-8，内容为 ASCII 时本就无乱码，可接受。
- **超长单段**：整段无换行的巨型段落会独占一页甚至溢出视口，MVP 接受；后续迭代引入段内硬切分。
- **大文件**：MVP 整本读入内存，数百 MB 的书会有压力；Roadmap 中「流式分页」届时在主进程分块读入解决，本次 IPC 接口已按字节传递、无需变更。
- **electron-vite 版本**：锁定模板生成时的主版本，避免小版本破坏性变更。
